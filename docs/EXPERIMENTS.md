# 怎样使用本书的实验教程

实验的作用是把一个抽象概念变成可观察的过程。阅读时先明确想解释的问题，再运行最小例子，最后沿代码和输出检查自己的解释。成功运行是起点；能说清输入怎样影响结果，才说明你理解了这个机制。

## 选择起点

第一次接触 Agent，可以从[第一章](../chapter1/README.md)的上下文实验开始；想理解检索，可以从[第三章](../chapter3/README.md)选择检索流水线；学习评估方法，可以进入[第七章](../chapter7/README.md)。每章导航给出了建议顺序，每个实验入口说明具体要观察什么。

## 准备运行环境

先进入所选实验目录，阅读其依赖文件和技术参考。各目录的运行环境可能不同，应分别准备虚拟环境，避免把全部实验的依赖装在一起。例如，使用 Python 的实验可以先执行：

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

这里以 Python 3.12 为例。仓库共享包要求 Python 3.11–3.13；使用其他版本前应核对项目约束。

有些实验还依赖仓库内的 `agentbook` 共享包。保持虚拟环境激活，在仓库根目录执行相应章节的安装命令，例如第二章使用 `python -m pip install -e ".[ch2]"`，再回到所选实验目录。该命令同时安装共享包和章节依赖；其他章节按技术参考选择对应依赖组。

随后按照该实验实际提供的依赖文件补充软件。并非所有实验都有 `requirements.txt`，也并非所有实验都使用同一 Python 版本。模型 API 实验需要对应凭据；训练、图像、语音和设备实验还可能需要显存、模型文件或硬件。先读清这些条件，再选择适合自己环境的路线。

在教程中，命令默认从当前实验目录执行，除非文字另有说明。将凭据配置在本地环境中，不要把它们写进共享的输出文件。

## 从一个例子开始

先选一个能手工判断的输入，运行一条完整路径。记录原始输入、关键中间结果和最终输出，再改变一个条件重跑。例如，研究上下文时保持任务和模型相同，只改变提供给模型的信息；研究检索时保持问题与文档相同，只改变检索策略。

阅读输出时，分清三个问题：程序是否顺利执行，任务是否完成，以及观察是否支持你的解释。接口报错不等于算法失败；最终答案正确也不代表中间过程可靠。模型生成有随机性，单个例子适合发现问题，稳定结论需要更多对照。

## 结合代码继续学习

每个实验入口给出建议阅读的源文件，并链接到同目录的技术参考。入口正文负责解释概念、操作顺序和结果含义；参考文档保留完整参数、安装细节、英文说明和历史运行记录。历史记录描述当时的环境，不保证在其他模型或依赖版本中得到相同结果。

完成一个练习后，尝试回答三个问题：哪个中间步骤最能解释结果？还有什么其他原因可能造成同样现象？下一次最小改动应该验证哪一种解释？带着这些问题阅读后续章节，比单纯重复命令更有帮助。
