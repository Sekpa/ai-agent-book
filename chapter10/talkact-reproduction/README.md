# 比较固定的快慢角色协作

[本章实验目录](../README.md) · [相关正文](../../book/chapter10.md) · [技术参考](REFERENCE.md)

语音交互要求及时响应，复杂任务又需要较长规划。固定快慢角色的设计试图让快速交互与较慢处理同时进行。本项目用对照任务研究这种分工。

## 理解实验

固定拓扑预先定义角色与消息路径，减少临时协调工作，但可能限制任务中的灵活分工。与单模型比较时，需要保持任务、用户行为与成功条件一致。

## 动手之前

本项目有多条运行路径。先按下文确定要观察的机制，再使用技术参考中对应的环境、数据与命令，避免混用不同路径的配置。 通用环境说明见[实验学习指南](../../docs/EXPERIMENTS.md)。

## 一步步观察

先阅读一条任务中的用户话语和系统响应时间线，辨认哪个角色在沟通、哪个在处理任务。按技术参考准备外部 TalkAct 环境，在本地受控任务上比较双角色与单模型路径。

## 怎样解释结果

响应更早不等于任务完成更早。应检查早期回复是否有用、信息是否同步，以及慢角色结果到达后是否纠正了临时判断。

## 继续思考

快速角色为了减少等待先作了承诺，慢角色随后发现不可行，系统应怎样处理？
