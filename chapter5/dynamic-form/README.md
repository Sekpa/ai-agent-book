# 用动态表单一次收集必要条件

[本章实验目录](../README.md) · [相关正文](../../book/chapter5.md) · [技术参考](REFERENCE.md)

当用户需求缺少目的地、日期或数量等信息时，连续追问可能很低效。本实验让 Agent 生成一个与当前任务相关的表单，把需要澄清的条件集中呈现出来。

## 理解实验

表单不仅是输入框集合，还表达字段类型、必填关系和级联逻辑。提交结果应变成结构化数据交回 Agent，而不是让模型再猜一次用户填写的含义。

## 动手之前

本项目有多条运行路径。先按下文确定要观察的机制，再使用技术参考中对应的环境、数据与命令，避免混用不同路径的配置。 通用环境说明见[实验学习指南](../../docs/EXPERIMENTS.md)。

## 一步步观察

先读技术参考中的示例需求，列出你认为必须补齐的字段。运行演示后，在浏览器中填写表单，刻意切换会影响其他字段的选项。检查提交的数据是否保留了这些变化。

## 怎样解释结果

表单能打开不等于澄清有效。检查是否询问了无关信息、是否漏掉关键约束，以及零值和空值是否被混淆。用户已经提供的信息也不应重复询问。

## 继续思考

哪些模糊需求适合表单，哪些仍需要自由对话才能理解？
